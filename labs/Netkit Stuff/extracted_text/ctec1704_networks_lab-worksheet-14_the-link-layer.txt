34.   Note the presence of redundant links between a0, a10, d0 and d1. These extra links
      create alternative paths between hosts.

      For example a message from h1 to h102 could be routed by any of these:
      h1 => a0 => d1 => a10 => h102
      h1 => a0 => d0 => a10 => h102
      h1 => a0 => d1 => d0 => a10 => h102
      etc

      In a worst case scenario, messages could simple cycle around the switches and
      possibly never arrive at their destination – know as the looping problem

      Fortunately another protocol - the Spanning Tree Protocol (STP) - was developed to
      prevent looping problems.

35.   Note the six directories (all empty), one for each virtual machine.

More extension activities: broadcast storms

41.    Turn on tcpdump, listening on d1


root@d1:~tcpdump -s0 -i sw0 -w /hostlab/d1-dump1.pcap


42.    Bring down selected links between the switches, for example on d0 try executing:


root@d0:~# ip link set eth3 down


Spanning Tree Protocol

Review: From the diagram above, you will emember that multiple routes exist between hosts:

eg
       h1 => a0 => d0 => d1 => a10 => h103

       or

       h1 => a0 => d1 => d0 => a10 => h103

This can lead to broadcast storms, where messages can loop continuously. To prevent this,
the Spanning Tree Protocol was developed. Read about this here and here.

43.    Bring all the links back up, then disable spanning tree on all the switches:


brctl stp sw0 off


44.    Make sure you have tcpdump running on one of the switches, then ping a non-existent
       host. See if you can achieve a broadcast storm.
