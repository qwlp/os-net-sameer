Netkit Labs

The example labs from lab 11 onwards are manipulated using the Netkit l…… commands,
such as lstart. Multiple xterms are started simultaneously and closed, all with a single
commend for each process.

A directory containing a complete Netkit lab will typically contain:

         ◦ one or more directories (usually empty)
           ▪ one for each virtual machine
         ◦ one or more .startup files
           ▪ again, one for each xterm
         ◦ one lab.conf file
           ▪ configures the ethernet connections and subnets for all machines.
         ◦ one lab.dep file
           ▪ speeds things up by starting the machines in parallel.

lab.conf

Use the cat command to review the contents of a file. NB only ever open a file in a text
editor if you mean to make some changes to it.


cat lab.conf


This file contains instructions to pre-configure the network interface settings for each virtual
machine. The man lab.conf command will give you further details as to how this file works.

9.     When you see a line in lab.conf such as:
             web-client[0]=lan

       it is equivalent to the terminal command:
                vstart web-client –eth0=lan

         •    web-client is the name of a network machine (in an xterm)
         •    the digits in the square brackets represent a network interface card
         •    lan represents a collision domain (in effect a network cable to allow
              connections between network cards on multiple network machines)

*.startup files

10.    There is one startup file for each Netkit virtual machine.

       These files contain the final instructions that are executed as each xterm starts, before
       you are presented with the login prompt of the virtual machine. The startup files for
       the web-client and web-server are very similar - they are only two lines long.

       Look at the content of each of these files in turn and draw a simple network diagram
       in your notes. Ensure you get the network card designation (eth0) and the IP address
       recorded accurately. Check your diagram with your lab tutor.

Accessing a web page with Telnet

The Telnet command can be used to check that the web server is behaving correctly by
requesting the default web page. In the web-client xterm window:


root@web-client:~# telnet 192.168.150.2 80


       This tells the web-client machine to use the Telnet application to access the web
       server daemon (how/why?) on port 80.

18.    Assuming that the web server is running, you will get a reply:

       Trying 192.168.150.2...
       Connected to 192.168.150.2.
       Escape character is '^]'.

19.    Press Enter. This gives blank line on the terminal – this is a requiment of the HTTP
       protocol.

20.    Enter the following:


GET / HTTP/1.0


21.    Press Enter a couple of times, and you will see the HTTP response message and the
       HTML web page code contained in the index.html file. The HTML code section is
       the payload.

Making Web Server Configuration Changes

The warning message, seen when starting the Apache web server, “Could not reliably
determine the servers name...” occurs because the the name of the server has not been added
to the Apache configuration. Therefore this message will be displayed each time the web
server is started and/or stopped. The httpd.conf file can be updated to set a value to remove
the message.

26.    Close the lab.


~/…/lab_11$ lcrash
~/…/lab_11$ lclean


27.    You need to create the httpd.conf file in your host system so that it is copied into the
       web-server xterm when it is executed.


~/…/lab_11$ mkdir -p web-server/etc/apache2/
~/…/lab_11$ gedit web-server/etc/apache2/httpd.conf &


NB the ‘&’ character opens the editor as a ‘background’ process. This means that the host
terminal prompt is still available to enter other commands whilst the file is being edited.

Other HTTP methods

Earlier you used the GET method of HTTP to access the remote web server. There are
several other methods that HTTP recognises:

34.    Use the telnet command to test the POST, HEAD and TRACE methods of the HTTP
       protocol. In the web-client xterm, enter:


web-client:~# telnet 192.168.150.2 80
Trying 192.168.150.2...
Connected to 192.168.150.2.
Escape character is '^]'.

POST / HTTP/1.0

HTTP/1.1 200 OK
Date: Fri, 16 Sep 2016 15:57:29 GMT
